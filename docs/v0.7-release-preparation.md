## Delta and compatibility

- Host-authorized recovery adds the optional recipient resolver and subject-bound
  store capability. Require unique canonical ownership, subject locking and
  transaction-bound reset invalidation when aliases change. Queued delivery
  rechecks recipient authorization and token currency. Reset never provisions a
  missing local credential. Email-less subjects with existing local credentials
  may reset through the authorized resolver; credential-less or SSO-only subjects
  cannot acquire passwords through recovery.
- Optional typed canonical identifiers appear in profile-scoped ID tokens and
  UserInfo as `authhub_identifiers`, never in access tokens. Nil preserves the
  previous wire format. The claim grants neither verified-email status nor
  authorization; existing issuer/subject bindings remain authoritative.
- The local common-password dictionary helper is opt-in. Defaults and login for
  existing credentials remain unchanged. An explicitly empty custom checker
  replaces the default dictionary; retaining built-ins requires its option.
- RBAC `Check` distinguishes ordinary denial from invalid input or dependency
  failure. Existing `Can` and `Require` retain their fail-closed behavior.
- PostgreSQL `CleanupBatch` is opt-in, with separate per-category limits and
  confirmed committed-phase counts. It neither schedules itself nor promises
  global atomicity, exhaustion after zero results, bounded query work, or
  reconstruction of uncertain commit outcomes.
- The email-less host-session example demonstrates canonical credential and
  host-owned transaction/session wiring. It is not a production session server.
- Current source requires Go 1.27.2 or newer and contains patched dependencies.
  Rebuild hosts with a supported patched compiler.

Schema remains 8; migration files are unchanged from v0.6.0. No database reset
or migration-history downgrade is appropriate. Existing required store interfaces
remain; opting into recovery requires its additional store capability.
No new supported package is added.

Before rollback, review newly used APIs, recovery policy and queued delivery.
An older schema-8 binary is not automatically a safe implementation of a newly
enabled host policy. Drain or invalidate affected recovery notifications before
removing that policy. Preserve canonical state, keys, tombstones and revocation
history. Older installations retain the [v0.6 upgrade contract](v0.6-migration.md).
